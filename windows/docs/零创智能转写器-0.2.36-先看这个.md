## 三、要转方言素材：三步

### 第 1 步：把 Qwen3ASR 整个目录放到 D 盘根目录

路径必须是 **`D:\Qwen3ASR\`**（内含 `models`、`venv`、`asr.py`、`asr_worker.py`）。
程序里的默认路径写死了这个位置。**路径里不要有中文或空格。**

一定要放别处的话，设两个环境变量指过去：

```bat
setx TRANSCRIBE_STUDIO_DIALECT_WORKER "X:\你的路径\asr_worker.py"
setx TRANSCRIBE_STUDIO_DIALECT_PYTHON "X:\你的路径\venv\Scripts\python.exe"
```

### 第 2 步：打开软件，选「方言」

「模型」下拉拉到最底下，选 **方言：昆明话等（较慢）**。

也可以在「专有词与错词修正」框里写一行 `#方言` —— 这行是暗号，
其余行会被当成**热词**喂给方言模型（采访里反复出现的人名、地名，
比如「李建国」「滇池」，一行一个写进去，识别率还能再提一点）。

### 第 3 步：等着

- 每个任务**开始前有约 27 秒在加载模型**，进度条不动是正常的，不是卡死。
- 之后大约 **1 倍实时**：1 小时素材 ≈ 1 小时。纯 CPU 就能跑，不需要显卡。
- **一次只跑一个方言任务**。程序支持并发 2，但方言模式吃 CPU，两个一起跑只会互相拖。
- 界面上的「语言」选 auto 或 zh 都行，**别选 en**（会按英文去认昆明话，直接废）。
- 产出格式和原来完全一样：`转写文档.md/.txt/.docx` + `转写字幕.srt` + `segments.json`，
  整理方式 / 模板 / 去重 / 字幕那些开关照旧生效。

## 四、给要动手改源码的人

```bat
cd lingxi-ai-transcribe\windows
npm install --registry=https://registry.npmmirror.com
npx electron-builder --win nsis
```

产物落在 `D:\outputs\release\`。

几个必须知道的点：

1. **`windows/python-embed/site-packages/sitecustomize.py` 是必需品**。
   它是 ffmpeg 环境变量补丁，靠便携 Python 的 `python311._pth` 里的
   `import site` 自动加载。删了它，转写必然失败。
2. **`windows/python/models/small/`（464 MB）按仓库惯例不入库**
   （`.gitignore` 忽略），本次为了让打包能离线产出可用安装包，
   把实际在用的权重放回了工作区。从 GitHub clone 的朋友需要跑
   `python scripts/fetch_models.py small` 拉下来。
3. **`node_modules` 也没入库**，本次为了方便离线重建一并放进来了。
4. Windows 版的核心三处：`windows/python/transcribe.py`（转写脚本）、
   `windows/src/`（界面）、`windows/extra/dialect-asr/`（方言组件）。
5. 详细的反补说明：`windows/docs/本机可用版反补说明.md`。
6. 方言组件部署详解：`windows/extra/dialect-asr/README.md`。

> 本机直连 GitHub / HuggingFace 极慢，npm 和依赖都走的 npmmirror / ModelScope。
