# 本机可用版 → 源码反补说明

日期：2026-09-19
版本：`windows/package.json` 由 `0.2.35` 升到 `0.2.36`

## 背景

`D:\零创智能转写器\local-transcribe-studio\` 里那套**实际在跑、能用**的程序，
是在 0.2.35 的基础上手工修过几个问题才跑通的。源码仓库此前没同步这些修复，
导致「从源码重新打包」出来的东西装完照样是坏的。本文档记录这次反补了什么。

## 一、三个修复

### 1. ffmpeg 环境变量补丁（不然转写必定失败）

**症状**：点转写就报 `RuntimeError: ffmpeg not found`。

**根因**：`src/main.js` 启动 `python/transcribe.py` 时只注入了
`TRANSCRIBE_STUDIO_CLOUD_AI_API_KEY`，从没注入 `TRANSCRIBE_STUDIO_FFMPEG` / `_FFPROBE`。
而 `transcribe.py` 的 `find_ffmpeg()` 查找顺序是：
① 环境变量 → ② macOS 的 homebrew 路径 → ③ 系统 PATH → ④ imageio-ffmpeg
在 Windows 上四条全落空，直接抛异常。

程序其实自带 `resources/ffmpeg/ffmpeg.exe` 和 `ffprobe.exe`，只是那段代码没用上。

**修复**：新增 `python-embed/site-packages/sitecustomize.py`（**本次已反补入库**）。
便携 Python 的 `python311._pth` 里启用了 `import site`，所以这个文件会在解释器
启动时自动加载，把随包 ffmpeg 的绝对路径写进环境变量，`transcribe.py` 第 ① 步就命中。

用 `setdefault`，外部显式设过就不覆盖。删掉这个文件即可完全回退，不改任何原有逻辑。

> 注：`python-embed/` 整体走 `extraResources` 随包分发，这个文件会自动进安装包，
> **不需要改 `build` 配置**。

### 2. Python 脚本版本错位（不然报 unrecognized arguments）

**症状**：
`Error invoking remote method 'transcribe-media': unrecognized arguments:
--subtitle-mode off --dedupe-mode normal --organizer local --document-template general`

**根因**：安装包里的界面层（`app.asar` 内 `src/main.js`）是新版，会传 11 个参数；
但自带的 `resources/python/transcribe.py` 是旧版，只认 5 个 —— 两层版本对不上。

**修复**：用仓库新版脚本（`windows/python/transcribe.py`，含全部参数支持）做
Windows 适配后替换。（**本次已确认：源码与本机安装版两个文件 `diff` 完全一致**）

### 3. Windows 适配细节（已含在 `windows/python/transcribe.py` 里）

- `bundled_binary()`：自动找到随包的 ffmpeg / ffprobe
- `resolve_model_ref()`：优先使用本地已有模型
- `.exe` 候选、通用错误文案

## 二、新增能力：方言识别（昆明话 / 云南话）

faster-whisper 对西南官话基本无能（「事情」→「死情」、「花叶」→「活业」），
改用阿里 **Qwen3-ASR-0.6B**（支持 22 种中文方言，含云南方言）。

### 代码改动

| 文件 | 改了什么 |
|---|---|
| `src/index.html` | 「模型」下拉新增 `方言：昆明话等（较慢）`（`value="dialect"`）+ 提示文案 |
| `src/renderer.js` | 方言模式的提示与确认文案 |
| `python/transcribe.py` | 新增 `is_dialect_model` / `split_dialect_directive` / `load_dialect_engine`，`load_engine()` 加方言分支 |
| `extra/dialect-asr/` | **新增**：`asr_worker.py`、`asr.py`、`README.md` |

### 调用链路

```
界面下拉 ──> main.js ──(--model dialect)──> resources\python\transcribe.py
                                              │ is_dialect_model() 判断
                                              ↓ 子进程（CREATE_NO_WINDOW）
                                    D:\Qwen3ASR\asr_worker.py（跑在 venv 里）
                                              ↓
                                    Qwen3-ASR 分块识别 → JSON segments
                                              ↓
                                    回灌原有后处理 → md/txt/docx/srt/segments.json
```

绕一层子进程的原因：便携 Python 里没有、也不该塞 torch，方言模型必须跑在
`D:\Qwen3ASR\venv` 里。路径可用这两个环境变量覆盖：

| 环境变量 | 默认值 |
|---|---|
| `TRANSCRIBE_STUDIO_DIALECT_WORKER` | `D:\Qwen3ASR\asr_worker.py` |
| `TRANSCRIBE_STUDIO_DIALECT_PYTHON` | `D:\Qwen3ASR\venv\Scripts\python.exe` |

界面上还支持一条暗号：在「专有词与错词修正」框写一行 `#方言`，
其余行当作**热词**喂给方言模型。详细部署见 `extra/dialect-asr/README.md`。

## 三、模型权重

faster-whisper 的 `small` 模型按仓库惯例**不入库**（`.gitignore` 忽略 `python/models/`），
由 `scripts/fetch_models.py small` 在构建时拉取。

但为了让第一次打包就能离线产出**开箱可用**的安装包，本次把本机实际在用的
`small` 权重（464 MB，6 个文件）放回了 `windows/python/models/small/`。
它被 git 忽略，只存在于工作区打包使用的文件树里。

## 四、从源码重建出「可用版」的步骤

```bat
cd windows
npm install --registry=https://registry.npmmirror.com
npx electron-builder --win nsis
```

产物在 `outputs/release/`。记得这一步必须**双击**验证：
非交互会话里用 `Start-Process` 启动 Electron 会直接退出（退出码 0），测不出真伪。

方言那一套不跟着安装包走，需要另外把 `D:\Qwen3ASR\` 整个目录拷到目标机器
（`extra/dialect-asr/README.md` 第三节有目录结构说明），或用上文那两个环境变量指过去。
